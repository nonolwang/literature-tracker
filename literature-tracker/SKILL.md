# 文献追踪助手

## 这个技能能帮用户做什么

1. **建文献库**：用户给一份参考文献清单（粘贴文本、BibTeX、截图题录均可），或者只说一个研究方向（任何学科，如"土壤碳汇""大模型对齐""肿瘤免疫"），即可得到一份结构化文献清单 `reading_list.jsonl`，每条含标题、作者、期刊/会议、日期、DOI、摘要。
2. **追新文献**：用户随时说"看看最近有什么新文献"，自动抓取距上次更新以来的新论文，按主题归类、按相关性排序，去重后追加进清单。
3. **精读讲解**：用户指定清单中任意一篇，得到一页纸讲解：研究问题、方法、核心结果、局限、与其研究方向的关系。
4. **邮箱推送**：绑定邮箱后，新文献简报一键发到邮箱；也可配置定时任务无人值守自动推送。
5. **研究讨论**：围绕库中文献讨论选题价值、方法对比、研究空白；讨论结论经用户同意可写回清单条目，长期积累。

## 上手流程（向用户展示并照此引导）

| 步骤 | 用户要做的 | 技能要做的 | 用户得到的 |
|---|---|---|---|
| 1. 初始化（一次性，约两分钟） | 告知研究方向或粘贴参考文献；如需推送再提供邮箱 | 生成项目目录、`tracker_config.json` 配置、为用户的领域定制主题词表 `topics.json` | 一个属于自己的文献库目录 |
| 2. 建库 | 确认首版清单是否符合预期 | 核实每条文献元数据、按主题分类 | `reading_list.jsonl` + 主题分布概览 |
| 3. 日常使用 | 一句话指令："更新文献" / "讲讲这篇" / "发本周简报到邮箱" | 抓取 → 分类 → 排序 / 精读 / 发信 | 更新后的清单、讲解、邮件 |
| 4. 自动化（可选） | 按教程配置一次定时任务 | 定时脚本自动抓取并推送元数据简报 | 定期到达的邮件简报 |

## 原则（必须遵守）

- 绝不凭记忆编造文献。清单中每条目的标题、作者、期刊、日期、DOI 必须来自脚本抓取结果或检索工具（paper_search / web 检索）的返回；核实不到的条目标记"未核实"并告知用户。
- 技能面向所有学科：检索关键词、主题词表、期刊源都从**用户的方向**生成，存放在用户的项目目录；技能自带的 `assets/examples/` 只是格式示例，不得当作默认内容使用。
- 脚本路径以加载时的技能目录为基准解析；用户数据（配置、清单、状态文件）一律放用户项目目录，技能目录保持只读。
- 邮箱授权码等凭据只通过环境变量读取，不写入任何文件，不出现在对话输出中。
- 首次推送先 `--dry-run` 预览给用户确认；之后用户一句话即可直接发送。
- 定时任务只做"抓取 + 分类 + 元数据简报"，不含 AI 讲解；带讲解的推送由用户在对话中触发。

## 初始化细节（模式 A：建库）

1. 确认四件事：研究方向（或种子文献清单）、想追踪的来源（默认 OpenAlex + arXiv 全库关键词检索；用户也可给定期刊 RSS 地址）、邮箱（可选）、项目目录位置。
2. 把 `assets/tracker_config.template.json` 复制为项目目录的 `tracker_config.json` 并填入用户配置；**根据用户的研究方向新写** `topics.json` 主题词表（5–10 个主题，各配中英文关键词，格式参照 `assets/examples/ag-econ-topics.json`）。
3. 用户给了种子文献：逐条用 paper_search 或 Crossref 核实元数据后写入 `reading_list.jsonl`；只给了方向：先跑模式 B（`--days 30`）做首次建库。
4. 汇报：总量、主题分布、时间跨度，并询问是否要精读其中几篇。

## 模式 B：更新追踪（抓取 + 归类）

```bash
python3 <技能目录>/scripts/fetch_papers.py --config <项目目录>/tracker_config.json \
    --state <项目目录>/tracker_state.json --output <项目目录>/new_papers.jsonl
python3 <技能目录>/scripts/classify_papers.py --input <项目目录>/new_papers.jsonl \
    --topics <项目目录>/topics.json --output <项目目录>/new_classified.jsonl
```

- `--state` 自动从上次抓取日期增量抓取并回写；首次运行用 `--days 30`。
- 分类后由智能体读新增条目的标题与摘要，按与用户方向的相关性排序、剔除明显不相关的（给出理由），再按 doi/url/标题去重后追加进 `reading_list.jsonl`。
- 中文文献：用 paper_search 的中文语料（zh）按主题检索补充；知网/万方无公开 API，用户看到的文献可给题录按同一 JSONL 格式手动录入。

## 模式 C：精读讲解

按 `references/paper-explainer.md` 的模板输出。只基于可获得的摘要/正文，明确标注哪些内容只是基于摘要的推断；数字必须来自原文，拿不到就说"摘要未报告"。

## 模式 D：邮箱推送

```bash
python3 <技能目录>/scripts/send_digest.py --config <项目目录>/tracker_config.json \
    --input <项目目录>/new_classified.jsonl --subject "文献简报 $(date +%F)" --dry-run
```

- 流程：模式 B 产出新条目 → 智能体为入选条目写 2–3 句中文导读（研究问题 + 方法 + 一个亮点）→ 对话中预览 → 确认后去掉 `--dry-run` 发送。
- 定时自动推送：按 `references/push-setup.md` 配置 launchd 或 cron；定时版推送元数据简报，与对话内推送共用 state 文件，不会重复。

## 模式 E：研究讨论

围绕清单内容讨论时先引用具体条目再展开；讨论结论经用户同意后作为 `note` 字段追加到对应条目。
